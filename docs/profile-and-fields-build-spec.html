iCapOS · Build specification

Profile and fields

An admin screen that owns the option lists every profile, form and matcher draws from — and shows which questions use them.

Status: specification only, nothing built · Route /admin/profile-fields · Permission manage_settings

1. Why

Industry values live in src/lib/icfo-events/sectors.ts as a hardcoded array of fourteen. There is no way to add, rename or retire one without a code change and a deploy. The same is true of stage, investor type and capital type.

The deeper problem is that the platform does not have one list — it has several, and they disagree:

  • EVENT_SECTORS — fourteen labels, used by the company profile, event registration and event tracks.
  • A second hardcoded copy of the same fourteen inside FounderConversationalOnboarding.tsx.
  • Odoo CRM industries, canonicalised at read time in src/lib/industries/canonical.ts — Fintech, Data/IoT, AgTech, Business Services, Hospitality. Outreach and /fit match against these.
  • Whatever an investor typed into the free-text “Preferred sectors” box.
  • Whatever enrich-investors.ts inferred from a firm’s website.

Matching bridges these with a synonym table (src/lib/matching/sector-synonyms.ts). That table works, but it is a workaround for not having one vocabulary.

2. Scope

In

  • An industry_options table, seeded with exactly the current fourteen, and an admin UI to add, rename, reorder and archive.
  • A read path — server loader plus client provider — that every picker uses, falling back to the code constants when the table is unreachable.
  • A Vocabularies tab listing five option sets: Industry, Stage, Investor type, Capital type, Geography.
  • A Fields tab listing every profile field, where it is asked, whether it is required, and its match weight.

Out

  • Amount of capital and check size. They stay numeric and keep their existing range-overlap scoring. Not converted to bands.
  • Any change to the eleven prose fields beyond labelling them as read by a person.
  • The matching core rewrite. Separate piece of work; this spec only surfaces its weights.
Naming. Fields keep the names they have today — “Amount of capital” on the founder side, “Typical check size” on the investor side. This work introduces no new field names.

3. Data model

One new table. Stage, investor type, capital type and geography stay in code for now and are rendered read-only on the Vocabularies tab until someone needs to edit them; the table below is the pattern each would follow.

create table if not exists public.industry_options (
  id          uuid primary key default gen_random_uuid(),
  slug        text not null unique,
  label       text not null,
  sort_order  integer not null default 0,
  archived    boolean not null default false,
  created_at  timestamptz not null default now(),
  updated_at  timestamptz not null default now()
);

create index if not exists industry_options_order_idx
  on public.industry_options (archived, sort_order);

alter table public.industry_options enable row level security;

-- Staff manage it.
drop policy if exists industry_options_staff_all on public.industry_options;
create policy industry_options_staff_all on public.industry_options
  for all using (public.is_staff()) with check (public.is_staff());

-- The public event registration form must read it while signed out.
-- Read-only, and the rows are question options rather than anyone's data.
drop policy if exists industry_options_public_read on public.industry_options;
create policy industry_options_public_read on public.industry_options
  for select using (not archived);

-- Seed: exactly today's fourteen, in today's order, so nothing moves on deploy.
insert into public.industry_options (slug, label, sort_order)
values
  ('fintech','FinTech',10), ('healthtech','HealthTech',20),
  ('saas','SaaS / B2B Software',30), ('edtech','EdTech',40),
  ('cleantech','CleanTech',50), ('ecommerce','E-commerce',60),
  ('ai-ml','AI / ML',70), ('real-estate','Real Estate',80),
  ('consumer','Consumer',90), ('deep-tech','Deep Tech',100),
  ('marketplace','Marketplace',110), ('logistics','Logistics',120),
  ('hardware','Hardware',130), ('other','Other',140)
on conflict (slug) do nothing;
The slug is permanent. Stored answers reference it. The label is display only and may be reworded at any time without touching a single record. This is the property that makes renaming safe, and it is the reason values must be stored as keys — see §7.

4. Read path

Every picker must resolve the same list, including client components and the signed-out registration form.

FileResponsibility
src/lib/industries/store.ts newlistIndustries() — server-only, wrapped in React cache(). Returns { slug, label, archived }[]. Never throws; on any error or empty table returns the code seed.
src/lib/industries/provider.tsx new<IndustryProvider value={…}> and useIndustries(). With no provider mounted the hook returns the code seed, so a missing provider renders exactly today’s behaviour rather than an empty picker.
src/lib/icfo-events/sectors.ts editEVENT_SECTORS stays, demoted from source of truth to seed and fallback. sectorLabel and isValidSectorSlug keep working against the loaded list.
src/lib/industries.ts editINDUSTRY_OPTIONS derives from the loaded list. industryOptionsFor(current) keeps its behaviour of prepending a non-canonical legacy value so it is never silently rewritten.

The provider is mounted where the pickers live rather than in the root layout, so marketing pages are not given a database read they do not need:

  • src/app/admin/layout.tsx
  • src/app/founder/settings/page.tsx and the founder onboarding page
  • src/app/investor/settings/page.tsx
  • src/app/events/[slug]/register/page.tsx and the public event pages

6. The page

Route /admin/profile-fields, guarded by manage_settings, added to the Administration group in src/lib/workspace-nav.ts between “My Profile” and “Feature Controls”, labelled Profile and fields.

House conventions apply without exception: PageHeader with eyebrow, actions right-aligned in each card’s own header, live search via src/lib/ui/live-search.ts with SearchStatus, counts reflecting the filter (“6 of 14”, never the unfiltered total), and matches highlighted.

Tab one — Vocabularies

Five cards, ordered by match weight. Each shows its values as chips and a line naming what it feeds.

ListWeightValues
Industry25The fourteen. Editable, opens into a detail view.
Stage20Pre-seed · Seed · Series A · Series B · Growth · Other
Investor type10Individual angel · Angel group / syndicate · Family office · Venture fund · Corporate / strategic · Other
Capital type10Equity · SAFE · Convertible note · Venture debt · Revenue-based
Geography10North America · Europe · LATAM · APAC · MENA · Africa · Global
Geography does not exist yet. Investors type geographies free-hand and founders type a country and a state. The seven regions above are a proposal, not a list in the codebase, and need sign-off before they are seeded.
Capital type is marked “never scores”. Founders answer it; no investor is ever asked. InvestorMatchProfile.capitalTypes is optional and the matching pass does not select it, so the factor drops out of every platform match. The card states this rather than presenting a healthy-looking list.

Industry detail view

The only list that needs more than inline chips, because it is the only one with meaningful per-value usage.

  • Table — Name · Key · founders · investors · registrations · actions.
  • Add — name typed, slug derived and shown locked before saving.
  • Rename — inline; the row states how many records display the new wording and that the key is unchanged.
  • Archive — removes it from new pickers. Records already carrying it keep it and still match. Nothing deletes.
  • Legacy values — free-text industries held by existing records appear with a legacy tag and an Adopt action that promotes one into a real option with its own key.
Counts come from live queries against companies, investor_profiles and registrations. A count that cannot be loaded renders as unmeasured with the query named — never as zero, and never as a placeholder figure.

Tab two — Fields

One row per field: name · audience · asked on · required · match weight. Three summary tiles: fields asked, fields scored, fields required but unscored.

Weights are read from the live matching config (DEFAULT_ENGINE_WEIGHTS and the admin override), never from a copy, so this tab cannot drift from what the matcher does.

Required can be toggled here. A field the matcher reads cannot be switched off without the UI stating what that costs.

The eleven fields scored by nothing — investment thesis, description, one-line pitch, use of funds, investor-fit notes, five key highlights, team summary, management team, annual EBITDA, annual revenue size, business entity — are listed as read by a person. Nine of them are required today, which is the fact this tab exists to expose.

7. Storage rule

Values are stored as keys and displayed as labels. This is not cosmetic. Two registration paths currently disagree — resolvedOptionsFor in registration-field-sets.ts returns o.label and discards the slug, so the field-set questions store "FinTech" while the networking interest chips on the same page store "fintech". sectorsOf compares those as raw strings, so a guest registered by staff shares no sector with one who registered themselves.

The fix belongs in this work: resolvedOptionsFor returns values, labels travel beside them in optionLabels, and every renderer resolves display through one helper.

8. API

RouteBehaviour
GET /api/admin/profile-fields/industriesList with usage counts. manage_settings.
POST /api/admin/profile-fields/industriesCreate. Slug derived server-side, uniqueness enforced, rejects a slug that already exists including archived.
PATCH /api/admin/profile-fields/industries/[id]Rename, reorder, archive or restore. Slug is immutable and a request attempting to change it is rejected.

No delete endpoint. Archiving is the only removal.

9. Tests

  • Store — returns the seed when the table is empty, unreachable, or the query errors; never throws; archived values excluded from pickers but still resolvable by sectorLabel.
  • Provider — useIndustries() with no provider mounted returns the code seed.
  • Slug — derived deterministically, immutable across renames, collision with an archived slug rejected.
  • Options — resolvedOptionsFor returns values not labels; resolveField attaches optionLabels only where value and label differ.
  • pg test — the migration applied against PGlite: table shape, RLS present, seed idempotent, re-running changes nothing.
  • Guards — select-columns.pg.test.ts and nav-routes.test.ts both pass with the new route and table.

10. Acceptance

  1. Adding an industry on the page makes it appear in founder onboarding, the founder company profile, the admin company editor, the CRM linked record, event registration, networking interests, event sector tracks, the sponsor catalog and the prospect list builder — with no deploy.
  2. Renaming one changes every display and breaks no stored answer.
  3. Archiving one removes it from pickers while existing records keep it and continue to match.
  4. With the table dropped or unreachable, every picker still renders the original fourteen.
  5. A guest registered by staff and one who registered themselves, both choosing the same industry, produce a match.
  6. Every count on the page is a live query or is labelled unmeasured. No placeholder figures.

11. Risks

Renaming a label that stored answers hold as textStorage rule in §7 lands in the same change; until it does, a rename is display-only and legacy text values are preserved
Industry becoming a filter rather than a signalExplicitly out of scope. A hard industry gate once emptied the outreach board despite thousands of contacts; industry contributes points and never excludes
