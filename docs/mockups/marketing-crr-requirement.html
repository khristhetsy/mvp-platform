The row does not disappear when the requirement is met — it stays as the record that it is met, and the date it happened. An item that vanishes when it passes leaves nobody able to confirm it ever did.

Everything here already exists. The row uses the same MirrorItem shape as every other item in the menu, the same status chips, the same drawer with problem / what's missing / how to solve, and the same ItemDiagnosis.ring that Preparation's CRR row already draws. The only genuinely new thing is one entry in the deploy menu definition and a condition that reads crr.outreachUnlocked.

Why repeat it in Marketing when Preparation already has it. Because the requirement does not stop applying when the founder advances. Today a company can be in Marketing with a CRR of 32 and nothing on the Marketing tab says so — the number lives one tab back, and the two items that depend on it fail silently. The row puts the requirement where the work is.

One thing worth deciding. Whether Held means the founder cannot start (a hard stop), or can start and staff see it flagged for review. Hard stop is cleaner to explain; review keeps a borderline company moving while someone looks. Either way the row reads the same — only the button behind “Automated outreach” changes.
