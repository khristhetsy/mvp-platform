Why the Showcase looks different

GroupLayoutWhy
Founder ShowcaseCard each, with the pitch lineThis is the reason an investor registers — the company and what it does is the content, not a credit
Presenting companiesTwo columns, name + personWho is on the programme. Scanned, not read
ExhibitorsOne lineA booth is a presence, not a session
Panelists—Rolled in with presenting companies unless you split them out

The Showcase pitch line is company_summary where it exists, falling back to bio, and the card drops to a bare name when both are empty. The Reuse previous presenters flow carries both across, so a founder who presented before arrives with their line intact.

The thing that has to be fixed first

role_label is free text, and four code paths spell the same role differently. Splitting on the exact string would produce three separate “Founder Showcase” headings in one email.

Where the presenter came fromStored as
Presenters manager dropdownFounder showcase
Accepted invitationFounder Showcase
Approved application, no label chosenfounder showcase
Invitation sent as role “Founder”Founder — a different role entirely

Grouping normalises before matching — lowercased, punctuation and spacing collapsed — so all three land in one section. Founder stays separate, because it is.

Worth knowing

Company still comes from headline, which is a topic field. Most of your roster holds the company already; one row reads “ClearPool Digital (cplx.oi)”. The block prints what the roster holds.

Order within each group is arbitrary — position is never written, so it is database order. Within a Showcase block that is more noticeable than in a booklet; alphabetical by company is the obvious default if you want one.

A role with nobody in it renders nothing — no heading, no empty state. Same rule the booklet’s presenter page follows.
