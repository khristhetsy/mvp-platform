Three different blanks, three different words. A dash that means four things is the same failure as a status nobody measures being shown as done.
  • not asked yet — the wizard step that collects it has not been reached. Actionable: chase the founder, and the panel links straight to their onboarding.
  • left blank — the step was completed and the founder skipped this optional field. Nothing to chase.
  • no portal account — the contact's email matches no founder profile, so there is no company to read. Today this renders exactly like the other two.
Which one applies is already knowable: companies.onboarding_step_state records the furthest step reached, and computeFounderOnboardingProgress already interprets it for the founder's own dashboard. The contact tab just never asks.
One thing to decide before this gets built. Steps 1–6 already capture amount, use of funds, business summary and industry — the four highlighted rows above — but the Founder Profile tab doesn't show them, so a partially-onboarded founder reads as completely empty. Do you want:
  • Show everything captured so far, with the per-field state above (what the mockup shows); or
  • Keep the sections hidden until onboarding completes, with just the amber strip saying where they stopped.
The first is more useful to a salesperson on a live call. The second is tidier.
Run this first — it decides what the plan fix actually is

In the Supabase SQL editor. It reports what the subscription row genuinely says for this contact, so the plan chip can be fixed for the right reason.

select p.email,
       s.plan_type,
       s.subscription_status,
       s.is_grandfathered,
       s.monthly_price_cents,
       s.created_at
  from public.profiles p
  left join public.subscriptions s on s.profile_id = p.id
 where p.email = 'vincent.n2013@gmail.com';

If plan_type is founder_basic — the row is right and the page is misreading it; a code fix.
If it is founder_free — the chip is telling the truth and the row needs correcting; then the code change is only the richer chip.
If there is no row at all — the account was never given a subscription, and getUserPlan is falling back to a default.
