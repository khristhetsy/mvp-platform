What the three select-alls do
Top-left box · all stages
Ticks all nine rows. With the Founder filter on it selects the four founder stages only — select all means all visible, never rows hidden behind the filter. The bar then offers Select all 9 explicitly.
Column ALL box · one person, every stage
Puts that person on every visible stage in one click — the common case for a super_admin who wants sight of everything. Un-ticking removes them from all of it, and if they were lead anywhere the confirm names those stages, because clearing a lead is not the same as clearing a watcher.
Row box · bulk over stages
Select any set of stages and act on all of them: assign, remove, set lead, set escalation, or copy one stage's whole setup onto them. This is the Odoo selection bar the platform already uses on Contacts and Opportunities.

Every stage has a lead, not just a list. Three people on a stage with no lead is three people each assuming one of the others has it. The lead is named in the alert (“Priya — Tinski Tech deleted 2 data-room files”) and the escalation clock starts from them.

Unassigned is a visible failure, not a silent one. A stage with no available assignee turns its row red, shows a Fix button, and routes to all super_admins. Note that Marketing above is technically assigned — Sara holds it — but she is away, so the design treats it as unassigned rather than letting alerts land in an inbox nobody is reading.

Load is shown because assignment without it is guesswork. 41 companies in Preparation at ~28 events/week is the difference between a fair split and one person quietly drowning. It is measured from the last 30 days of real events — so it reads unmeasured until the emitters ship, rather than showing a plausible zero.

What this needs in the schema. A small table — activity_stage_assignments (audience, stage, user_id, is_lead, escalate_after_minutes, escalate_to). Nine rows per staff member at worst. Nothing here needs a per-event join.

Select all has one trap worth naming. Ticking a column ALL box makes someone a watcher on every stage, which is cheap. Un-ticking it can silently strip a lead — and a stage with no lead is a stage where three people each assume someone else has it. So the un-tick confirms, naming the stages where they lead, and the row stays red until a new lead is picked.

One thing to decide. Whether “on leave” is real. The design reads staff availability to demote a lead, but nothing on the platform records it today — either that gets a field, or the out-of-office row comes out and Marketing shows as assigned when it effectively isn't.
