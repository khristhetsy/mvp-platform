Both rules already exist in code. lib/uploads/policy.ts exports PDF_ONLY with maxBytes: 25 * 1024 * 1024 and a validateFile() whose messages are the two red lines above, word for word. The deck rule is a reuse, not new work — and the same limit is already used by SPV documents, admin tasks and e-signature, so 25 MB stays one number.

Video is URL-only by design. Nothing about hosting video is built, and a 6-minute pitch is larger than the entire 25 MB document ceiling. Accepting a link keeps it that way, and the rejection message says where to put the file rather than just refusing it.
One thing to confirm before this is built: where the stage link comes from. EventPresenter.meetingUrl exists and is editable today, but nothing generates it. Three options, and they are not equivalent:
  • Google Meet, generated per presenter — the Google Calendar integration (GOOGLE_CLIENT_ID/SECRET, TOKEN_ENCRYPTION_SECRET) is already configured, so a calendar event with conferencing gives each presenter their own Meet link plus a real calendar invite. What the mockup shows.
  • Whereby room — isLiveVideoConfigured() and the event's own video/whereby module already run the live sessions. A presenter link would then be the same room the event uses, not a separate Meet.
  • Paste it yourself — keep meetingUrl manual and just surface it on the invite page. No new integration at all.
The event already has a live-session mechanism in Whereby, so generating Google Meet links alongside it would give one event two video systems. Worth deciding deliberately rather than by default.
