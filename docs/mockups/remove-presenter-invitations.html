The database

If you never ran docs/sql/event-presenter-invites.sql — nothing to do. Deleting the migration file is the whole job.

If you did run it — a drop script drops event_presenter_invites, the event_invite_status enum, and the five materials columns on event_presenters (video_url, deck_path, deck_filename, deck_bytes, materials_updated_at). Every one is guarded with if exists, so it is safe either way.

One thing cannot be undone: the migration added 'exhibitor' to the speaker_application_kind enum. Postgres has no DROP VALUE. It stays, unused and harmless — removing it would mean rebuilding the type and every column that uses it, which is not worth it for a value nothing writes.
