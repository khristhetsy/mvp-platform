What comes across

Copied

  • Name, email — the identity
  • Role label — Presenter, Founder Showcase…
  • Bio and company summary — optional, ticked by default
  • Links
  • Headshot — the stored file, not a new upload
  • Talk topic — optional, unticked by default

Left behind — event-specific

  • Session assignment — this event’s sessions are different
  • Slot date, time and timezone
  • Meet link — a room from last event would be dead
  • Video URL and pitch deck — re-collected per event
  • The originating application

Talk topic is unticked by default because a headline like “ClearPool Digital (cplx.oi)” belongs to the talk they gave, not to them — carrying it silently is how a booklet ends up advertising last quarter’s session. Tick it when it’s the same talk.

Worth knowing

There is no “person” record. event_presenters holds one row per person per event — nothing links Jamie at Newport Beach to Jamie at Las Vegas. This list is built by collapsing past rows on profile_id, falling back to lowercased email, then name. Two rows spelled differently with no email will show as two people; the search box is how you catch that.

A copy, not a link. Editing the bio on the new event does not change the old one, and fixing a typo on the old event does not reach the new one. That is the right behaviour for a booklet you have already printed — just don’t expect one to follow the other.

Order still isn’t solved. Copied presenters land at position 0 like every other row, so booklet order stays whatever the database returns. Separate problem, separate fix.
