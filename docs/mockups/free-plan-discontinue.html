Discontinue the free plan

Ticket: new founders can still sign up free. Findings first — one of your three points has an answer you won't like.

What the code actually does

  1. Your removal was reverted, same day. d368fdb (28 Aug) removed the free tier — "founders require a paid plan". b7ae05b, also 28 Aug, reinstated it: "restore previous-build pricing/signup/marketing". Current behaviour is what that commit restored.
  2. Every new founder is granted free automatically. defaultPlanForRole() returns founder_free for role founder, and isAutoGrantSignupPlan() returns true for it — so it's granted without ever reaching checkout.
  3. There is no grandfathering. At all. founder_free renders as the label "Free (grandfathered)", but nothing checks a signup date and no flag exists. Martin Goldberg (2023) and a founder who signed up this morning show the identical badge.
  4. The $49 plan is founder_basic — PLAN_PRICES.founder_basic = 4900, shipped in 5786f92 on 16 Sep 2026. That date is the natural cutoff.

Point 3 — how are grandfathered accounts identified?

Today: they aren't. There is no flag and no date check. The word "grandfathered" is display text on the plan label and nothing more.

So this needs deciding, not confirming. Two options, and I'd take the second:

(a) By date — treat subscriptions.created_at < cutoff as grandfathered. No migration, but it's a rule recomputed on every read, easy to get wrong in one place, and it silently re-grandfathers anyone whose row is ever recreated.

(b) By an explicit flag — add subscriptions.is_grandfathered boolean, backfill it once from the cutoff date, then never compute it again. The account carries its own status, an admin can grant or revoke it deliberately, and the label finally means something. One migration, which you'd run in the SQL editor.
